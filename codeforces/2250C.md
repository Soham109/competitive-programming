# 2250C

> [Problem on Codeforces](https://codeforces.com/problemset/problem/2250/C)

## Idea

Fix a candidate final length $m$. Once $m$ is fixed, an element's validity at position $j$ depends only on $j$ and $m$ (since the right rank is $m-j+1$), never on which other elements were chosen. That means checking feasibility for a given $m$ reduces to a greedy slot-filling problem, scan the elements left to right and always grab the earliest one that can legally occupy the next open slot. If greedy fills all $m$ slots, $m$ is achievable.

## Approach

1. For a fixed $m$, slot $j$ needs an element whose left rank exclusion $[l_i, r_i]$ misses $j$ and whose right rank exclusion $[u_i, v_i]$ misses $m-j+1$.
2. Scan the elements in original order while tracking the next slot $j$ we still need to fill, starting at $j=1$. When element $i$ is valid for the current $j$, assign it there and advance to $j+1$; otherwise skip it.
3. This greedy choice is safe because an element's eligibility only depends on $(j,m)$, not on identity. If some later element could fill slot $j$, it remains available (or its role can shift) for a later slot too, so taking the first eligible element for $j$ never costs us a slot we could have filled otherwise.
4. If $j$ exceeds $m$ by the end of the scan, all $m$ slots got filled, so length $m$ is achievable.
5. Try $m$ from $n$ down to $1$ and report the first feasible value, since larger $m$ is strictly better; if none works, the answer is $0$.

## Complexity

- **Time:** $O(n^2)$, since each of the $O(n)$ candidate values of $m$ is checked with one $O(n)$ greedy scan.
- **Space:** $O(n)$ for storing `l`, `r`, `u`, `v`.
