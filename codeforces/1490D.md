# Permutation Transformation

> [Problem on Codeforces](https://codeforces.com/problemset/problem/1490/D)

## Idea
The tree is defined recursively by "find the max, split around it," so the construction itself is the algorithm. Each time we descend into a subarray we cross exactly one edge, so the depth of $a_v$ equals the number of times $v$'s position gets isolated by a max-split before it becomes the max of its own range.

## Approach
1. Write a recursive function that takes a range $[l, r)$ of the array and a current depth $d$, starting with $d = 0$ over the whole array, since the outermost maximum is the root at depth zero.
2. Find the index $m$ of the maximum element in $[l, r)$ by a linear scan, because that element is forced to be the root of this subtree by the problem's own construction rule.
3. Record $d_m = d$ for that position, then recurse on the left part $[l, m)$ and the right part $(m, r)$ with depth $d + 1$, since both sides become independent subtrees one edge deeper.
4. An empty range simply produces no recursive call, which matches "no left/right child" when the maximum sits at the boundary of the range.
5. Because $n \leq 100$, the naive $O(n)$ scan for the maximum at every recursive call is affordable even in the worst case of an already-sorted (fully skewed) permutation, where the recursion degenerates into a chain of depth $n$.

## Complexity
- **Time:** $O(n^2)$ per test case, from up to $n$ levels of recursion each scanning $O(n)$ elements for the maximum.
- **Space:** $O(n)$ for the recursion stack and the depth array.

## Notes
Depths are tied to array positions, not values, so store them in an array indexed by $v$ (the original index) and print in that order rather than in the order subtrees are visited.
