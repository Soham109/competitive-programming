# Marenol (easy version)

> [Problem on Codeforces](https://codeforces.com/problemset/problem/2254/C1)

## Idea

Look at what a single operation actually moves. In $\mathtt{001} \to \mathtt{100}$ the lone $1$ jumps from index $i+2$ to index $i$, a shift of $2$, and in $\mathtt{110} \to \mathtt{011}$ the lone $0$ jumps by $2$ in the same way. Every character that moves shifts by exactly two positions, so it never changes parity of its index. That means the number of $1$s sitting at even indices and the number of $1$s sitting at odd indices are each invariant under any sequence of operations.

## Approach

1. Split each string's positions into two classes by parity of index and count the $1$s in each class, since that count can never change no matter how many operations are applied.
2. For string `a` this gives `ea` ($1$s at even indices) and `oa` ($1$s at odd indices), and analogously `eb`, `ob` for `b`.
3. A transformation from `a` to `b` requires `ea == eb` and `oa == ob`, because the operations preserve these two quantities exactly.
4. This is also sufficient, since within a fixed parity class the length-$3$ swaps let any $1$ hop past any $0$ two steps at a time, effectively bubble-sorting the $1$s to any target arrangement as long as the same-parity counts agree.
5. Output "YES" exactly when both parity counts match, "NO" otherwise.

## Complexity

- **Time:** $O(n)$ per test case, a single pass over both strings.
- **Space:** $O(1)$ extra beyond the input strings.
