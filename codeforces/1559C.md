# Mocha and Hiking

> [Problem on Codeforces](https://codeforces.com/problemset/problem/1559/C)

## Idea
The fixed roads $1 \to 2 \to \cdots \to n$ already form a Hamiltonian path over villages $1$ through $n$, so the only real question is where village $n+1$ can be spliced into that chain. The array `a` answers exactly this, since `a[i]` tells us whether village $i+1$ points out to $n+1$ or gets pointed into by it, so $n+1$ can only be attached at one of the two ends of the chain, or dropped in between two consecutive villages $i+1$ and $i+2$ where village $i+1$ points out to $n+1$ and $n+1$ points into village $i+2$.

## Approach
1. Check `a[n-1]`, the edge belonging to the last village in the chain. If `a[n-1] == 0`, village $n$ has a road straight to $n+1$, so extending the ready-made path $1,2,\ldots,n$ with $n+1$ at the end keeps every edge valid, because the chain edges are untouched and the one new edge is exactly the one `a[n-1]` describes.
2. Otherwise check `a[0]`, the edge belonging to the first village. If `a[0] == 1`, then $n+1$ has a road into village $1$, so prepending $n+1$ before the chain works by the same argument in reverse, since the only new edge needed is $n+1 \to 1$, which is guaranteed to exist.
3. If neither end works, we know `a[0] == 0` and `a[n-1] == 1`, meaning the sequence starts by pointing away from $n+1$ and ends by pointing toward it. A binary sequence that starts at $0$ and ends at $1$ must switch somewhere, so there is some index $i$ with `a[i] == 0` and `a[i+1] == 1`. At that position village $i+1$ has a road to $n+1$ and $n+1$ has a road to village $i+2$, so splicing $n+1$ between them, giving $1,\ldots,i+1,\,n+1,\,i+2,\ldots,n$, replaces the single chain edge from $i+1$ to $i+2$ with two valid edges through $n+1$ without disturbing the rest of the chain.
4. Because this third branch only runs when `a[0] == 0` and `a[n-1] == 1`, the required $0 \to 1$ transition is guaranteed to exist somewhere in `a`, so scanning for it always succeeds before falling through to the trailing `-1`, which is why that output line never actually fires for this problem.

## Complexity
- **Time:** $O(n)$ per test case, the array `a` is scanned a constant number of times.
- **Space:** $O(n)$ for storing `a`.

## Notes
The trailing `cout<<-1` is unreachable here, because reaching that third branch already forces `a[0] == 0` and `a[n-1] == 1`, which guarantees the $0 \to 1$ transition the loop searches for.
