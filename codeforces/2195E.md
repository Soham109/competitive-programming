# Idiot First Search

> [Problem on Codeforces](https://codeforces.com/problemset/problem/2195/E)

## Idea

Whenever Bob steps down into an internal vertex $v$ for the first time, he is guaranteed to finish exploring its whole subtree and come back up to $v$ with the letter erased, because each vertex goes through the states nothing, `L`, `R`, nothing. So the time spent inside a subtree depends only on the subtree itself, and it satisfies a simple recurrence. Since the cleanup also resets every letter, climbing from a vertex to its parent always starts from a freshly blank parent, which lets the answers chain along the path to the root.

## Approach

1. We define `dp[x]` as the time Bob needs, starting at a blank vertex $x$, to explore the subtree of $x$ and be standing on $x$ again with everything below it blank. A leaf needs no exploration, so `dp[x] = 0` there. For an internal vertex, Bob goes left (1 move), finishes the left subtree (`dp[l[x]]`), returns (1 move), goes right (1 move), finishes the right subtree (`dp[r[x]]`) and returns (1 move). This gives `dp[x] = 4 + dp[l[x]] + dp[r[x]]`, and it is valid because each child is entered blank and left blank, so the two subtrees do not interfere.

2. Starting at $k$, Bob first finishes the whole subtree of $k$, which costs `dp[k]`, and ends on $k$ with the letter `R` still written. One more move takes him to the parent, which is `+ 1`. The letters on every ancestor are exactly as they were at the start, so the situation at the parent is the same as the original problem started from the parent, except that the parent already has a letter written because Bob came up from one of its children.

3. The mismatch in step 2 is handled by the structure of the walk. Bob arrives at the parent $p$ from the child he started in, and the remaining work is the rest of $p$'s exploration plus the climb above. We express it as `ans[x] = dp[x] + 1 + ans[parent[x]]`, which treats arriving at $p$ as if Bob had begun at $p$ itself. This holds because an unwritten `L` at $p$ means the left subtree is still to be done, an `R` means only the right remains, and in both cases the cost of finishing $p$ and everything above matches the recurrence's accounting of the full run from $p$. The base `ans[0] = 0` ends the chain at the root, since `parent[1] = 0`.

4. The recurrence for `dp` needs children before parents, while `ans` needs parents before children. A breadth first order stored in `order`, built from vertex $1$ by pushing `l[x]` and `r[x]`, gives both for free. Scanning `order` backwards fills `dp` bottom up, and scanning it forwards fills `ans` top down, so every value is computed once from values that are already final. Each sum is taken $\pmod{10^9+7}$ because the true times grow exponentially with depth.

## Complexity

- **Time:** $O(n)$ per test, since building `order`, filling `dp` and filling `ans` each visit every vertex once.
- **Space:** $O(n)$ for `l`, `r`, `parent`, `dp`, `ans` and `order`.

## Notes

- Vertex $0$ is only a sentinel with `ans[0] = 0`, and `parent[1] = 0` is left at its default, so no special case is needed for the root's child.
- `dp` and `ans` use `long long`, and each addition reduces modulo $10^9+7$ immediately, so sums of at most three residues never overflow.
