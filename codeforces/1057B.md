# DDoS

> [Problem on Codeforces](https://codeforces.com/problemset/problem/1057/B)

## Idea

The condition "the total requests over a window exceed $100$ per second on average" is awkward because the threshold $100 \cdot t$ changes with the window length $t$. Subtracting $100$ from every value turns that moving target into a fixed one, since a window $[l, r]$ is an attack exactly when $\sum_{i=l}^{r} (r_i - 100) > 0$, a sum we can compare against zero regardless of how long the window is.

## Approach

1. Rewrite the attack condition as a sum of shifted values being positive, because $\sum r_i > 100t \iff \sum (r_i - 100) > 0$, which removes the dependence on the window length from the comparison.
2. For each left endpoint `l`, walk the right endpoint `r` across the rest of the array while keeping a running total `sum` of `a[r] - 100`, because extending the window by one position only ever adds a single shifted term to the previous total, so the running sum needs no recomputation.
3. Whenever `sum` becomes positive at some `r`, the window `[l, r]` is a valid attack, so we update `ans` with `r - l + 1`, since we only care about the longest such window and every valid window is checked once its right endpoint is reached.
4. Repeating this for every starting index `l` covers all $O(n^2)$ possible windows, which is affordable because $n \leq 5000$ keeps the total work within the time limit.

## Complexity

- **Time:** $O(n^2)$, from trying every pair of endpoints $(l, r)$.
- **Space:** $O(n)$ for storing the request counts `a`.
