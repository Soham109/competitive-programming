# DDoS

> [Problem on Codeforces](https://codeforces.com/problemset/problem/1057/B)

## Idea

A window of length $t$ is an attack exactly when its sum exceeds $100 \cdot t$, so subtracting $100$ from every element turns the condition into "the sum of the shifted window is positive." That reformulation lets us check all $O(n^2)$ windows by extending a running sum from each left endpoint instead of recomputing sums from scratch.

## Approach

1. Rewrite the DDoS condition $\sum r_i > 100t$ as $\sum (r_i - 100) > 0$ over the same window, because subtracting a constant $100$ from each term and comparing to $0$ is equivalent to comparing the original sum to $100t$.
2. Fix a left endpoint `l` and initialize `sum = 0`, since every window starting at `l` is examined independently.
3. Grow the right endpoint `r` from `l` to $n-1$, adding `a[r] - 100` to `sum` at each step, which incrementally maintains the shifted sum for the window $[l, r]$ without recomputation.
4. Whenever `sum > 0`, the window $[l, r]$ is a valid attack, so update `ans` with `r - l + 1` if it's larger.
5. Because `n <= 5000`, the nested loops over all $O(n^2)$ pairs $(l, r)$ run comfortably within the limits, so no smarter data structure is needed even though the commented-out two-pointer attempt shows the author first tried and abandoned a linear approach.

## Complexity

- **Time:** $O(n^2)$, from the double loop over all start and end pairs.
- **Space:** $O(n)$, for storing the array `a`.
