# Array Recoloring

> [Problem on Codeforces](https://codeforces.com/problemset/problem/2075/B)

## Idea

The key observation is that the cost of painting the array is determined by the sum of the initial $k$ chosen elements and the last red element to be painted. To maximize the cost, the $k$ initially chosen elements should be the largest ones in the array, as they directly contribute to the cost. Additionally, the last red element to be painted will always be one of the largest remaining red elements adjacent to a blue element, so the optimal choice is to ensure this element is also as large as possible.

## Approach

1. **Sort the array in descending order:** Since we aim to maximize the cost, sorting the array in decreasing order ensures that the largest elements are considered first.
2. **Select the top $k$ elements:** Choose the first $k$ elements from the sorted array as the initial blue elements. These elements directly contribute to the cost, so selecting the largest $k$ guarantees the highest possible contribution.
3. **Add the $(k+1)$-th element to the cost:** After the first $k$ elements are chosen, the $(k+1)$-th largest element will be the last red element to be painted, as it will be the largest red element adjacent to a blue element. Adding this value to the sum of the $k$ largest elements gives the maximum cost.

## Complexity

- **Time:** $O(n \log n)$ per test case, dominated by the sorting step. Since the sum of $n$ over all test cases is bounded by $5000$, the total complexity is $O(5000 \log 5000)$.
- **Space:** $O(n)$ per test case to store the array.

## Notes

- The algorithm leverages sorting to simplify the problem into selecting the largest $k+1$ elements, ensuring that the computation is both efficient and straightforward.
