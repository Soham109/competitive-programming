# Predominant Frequency Division

> [Problem on Codeforces](https://codeforces.com/problemset/problem/2242/B)

## Idea

The key observation is that the constraints for each of the three parts of the array can be reduced to tracking a single balance value. Specifically, for the left part, the number of $1$s must be at least the total number of $2$s and $3$s, which can be expressed as a balance $l = count(1) - count(2) - count(3)$. Similarly, for the middle part, the condition translates to checking whether this balance remains non-negative. By maintaining a prefix sum of this balance, we can efficiently determine if a valid split exists.

## Approach

1. Compute a prefix balance array `p` for the input array `a`, where $p[i]$ represents the balance $s$ after processing the first $i+1$ elements. For each element $a[i]$, update $s$ as follows:
   - Increment $s$ for $a[i] = 1$.
   - Decrement $s$ for $a[i] = 3$.
   - Leave $s$ unchanged for $a[i] = 2$.

2. Traverse the array to determine possible splits:
   - Maintain a running balance `l` for the left part, starting at $0$. Update `l` by incrementing for $a[i] = 1$ and decrementing for $a[i] = 3$.
   - Track the minimum value of `p[i]` encountered so far for the left part (`mn`). This ensures that the condition for the left part is satisfied up to index $i$.

3. For each potential split point $j$ (where the middle part starts):
   - Check if the left part (ending just before $j$) satisfies its condition by verifying that $mn \leq p[j-1]$.
   - Check if the middle part (starting at $j$) satisfies its condition by verifying that $p[j] \geq mn$.

4. If both conditions are satisfied for some split point, output "YES" and terminate. Otherwise, output "NO".

## Complexity

- **Time:** $O(n)$ per test case. Computing the prefix balance and checking all potential split points both require linear time.
- **Space:** $O(n)$ for the prefix balance array.

## Notes

- The prefix balance array `p` is key to reducing the problem to a single-pass check for valid splits.
- The use of a running minimum (`mn`) allows efficient validation of the left part's condition without recomputing the minimum repeatedly.
- The constraints on $n$ ensure that the solution is computationally feasible within the given limits.
