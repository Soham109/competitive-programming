# Riptide

> [Problem on Codeforces](https://codeforces.com/problemset/problem/2254/A)

## Idea

With $a, b, c \leq 10$, the total number of tokens is at most $30$ and every round moves the extreme values one step closer together, so the game can't run for more than a handful of rounds. That makes direct simulation of the described process cheap enough to just do literally, no formula needed.

## Approach

1. Sort `a` so the current minimum sits at `a[0]` and the current maximum at `a[2]`, which is exactly what the rule "most gives to fewest" needs.
2. Re-sort at the top of every loop iteration since the ranking of the three players can change after each transfer.
3. Check `a[0]==a[1] || a[1]==a[2] || a[0]==a[2]` and stop as soon as any pair matches, matching the rule that the game ends the moment two players are tied.
4. If no pair is tied, apply the round directly with `a[0]++; a[2]--`, giving one token from the largest holder to the smallest, and bump the round counter `r`.
5. Because the values are bounded and the gap between max and min shrinks (or a tie appears) every round, the loop provably terminates and `r` ends up holding the exact round count.

## Complexity

- **Time:** $O(1)$ per test case since $a, b, c \leq 10$ bounds the number of rounds by a small constant, giving $O(t)$ overall.
- **Space:** $O(1)$, only the three-element array `a` is used.
