# Riptide

> [Problem on Codeforces](https://codeforces.com/problemset/problem/2254/A)

## Idea

Every round moves exactly one token from the maximum to the minimum, so the multiset of values only ever gets closer together. Since $a, b, c \leq 10$, the game ends after at most a handful of rounds, and we can just simulate it directly rather than derive a closed form.

## Approach

1. Sort the three values so the current minimum and maximum are always at the ends of the array, because the rule only cares about who is strictly largest and strictly smallest.
2. Before each round, check whether any two of the three values collide, since that is the stopping condition stated in the problem.
3. If no collision exists, the largest gives one token to the smallest, matching `a[0]++; a[2]--` after sorting.
4. Re-sort after the transfer, because the identity of the max and min can change between rounds.
5. Count rounds until a collision appears, then output that count.

## Complexity

- **Time:** $O(1)$ per test case, since values stay bounded near their starting range and the loop terminates in a constant number of rounds.
- **Space:** $O(1)$, just the three counters.
