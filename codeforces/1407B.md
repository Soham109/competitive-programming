# Big Vova

> [Problem on Codeforces](https://codeforces.com/problemset/problem/1407/B)

## Idea

Lexicographic comparison decides everything at the first position where two sequences differ, so a larger $c_i$ at an earlier position always beats anything that could happen later. That makes a greedy choice correct, because at each position we can pick the unused number that gives the largest prefix gcd, given the prefix already fixed. The prefix gcd can only stay the same or shrink as more numbers are added, and it always divides the previous value, so nothing we do later can undo the benefit of a large early value.

## Approach

1. Since $c_1 = b_1$, the first position is maximized by putting the largest number first, and in general $c_i = \gcd(c_{i-1}, b_i)$ depends only on the current running gcd and the number we place next. We store the running gcd in `g` and start it at $0$, because $\gcd(0, x) = x$. This means the very first step needs no special case, since the "best gcd with `g`" of any number is just the number itself.

2. At every step we scan all numbers not yet marked in `used` and keep the index `best` with the largest $\gcd($ `g` $, a_j)$. Every unused number is a legal candidate for $b_i$, and the value of $c_i$ that each one produces is exactly that gcd. Taking the maximum therefore gives the largest $c_i$ achievable after the earlier choices, and by the lexicographic argument above this cannot hurt any later position.

3. When two candidates $x$ and $y$ give the same gcd $g'$ with `g`, it does not matter which one we take. If we take $x$, then $y$ is still available and $\gcd(g', y) = g'$, which is the largest value $c_{i+1}$ could possibly have since it cannot exceed $g'$. So $y$ can follow immediately with no loss, and the strict `>` comparison, which keeps the first index that reached the maximum, is enough.

4. After choosing `best` we mark it in `used`, replace `g` with $\gcd($ `g` $, a_{best})$, and print `a[best]`. Updating `g` is what carries the prefix gcd forward to the next step. Once `g` reaches $1$, every remaining candidate yields $1$, so the rest is filled in arbitrarily, and the same scan handles that case without any special branch.

5. Repeating this for all $n$ positions uses every number exactly once, because each pick is marked in `used` and skipped afterwards. The printed order is $b$, and by construction each $c_i$ is the largest value possible given the earlier ones.

## Complexity

- **Time:** $O(n^2 \log A)$ where $A \leq 10^3$ is the maximum value, since each of the $n$ steps scans up to $n$ candidates and each scan does a gcd costing $O(\log A)$.
- **Space:** $O(n)$ for the array `a` and the `used` flags.

## Notes

- The sum of $n$ over all test cases is at most $10^3$, so the quadratic scan is comfortably fast.
- `gcd(g,a[j])` is recomputed for `best` on every comparison. This is harmless at these limits and keeps the code short.
