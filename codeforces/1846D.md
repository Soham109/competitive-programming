# Rudolph and Christmas Tree

> [Problem on Codeforces](https://codeforces.com/problemset/problem/1846/D)

## Idea

All the branches are the same triangle, moved up the trunk by different amounts. A triangle gets thinner the higher you go, so where two branches meet, the lower one is always the thinner of the two. It has climbed further toward its own tip by that height. This means a branch can only lose area to the branch right above it. Anything hidden under a branch further up is hidden under the one in between as well, and is not lost twice. So add up the area of all $n$ triangles, then take away the shared piece for each neighbouring pair.

## Approach

1. Branch $i$ runs from height $y_i$ up to $y_i + h$, and at a height $t$ inside that range it sticks out $\frac{d}{2}\left(1 - \frac{t - y_i}{h}\right)$ on each side of the trunk. The higher $t$ is, the smaller that gets. Two branches at the same height only differ in where their bases are, so the one with the lower base is narrower there.

2. Only neighbours need checking. Suppose a point belongs to both branch $i$ and branch $i + 2$. It lies above $y_{i+2}$, so it lies above $y_{i+1}$ too, and it is narrow enough to fit inside branch $i$, so it fits inside the wider branch $i+1$ as well. It is already inside the neighbouring pair's shared piece, so nothing extra needs subtracting. That is why the loop only looks at `heights[i+1] - heights[i]`.

3. Above $y_{i+1}$ branch $i$ is the thinner one, so the piece the two share is just the top of branch $i$, cut off at the base of the branch above. It is the same triangle shape shrunk down, standing $h - dis$ tall instead of $h$, where `dis` is the gap. Shrinking by $\frac{h - dis}{h}$ makes the base $\frac{d(h - dis)}{h}$, so the piece has area $\frac{d(h - dis)^2}{2h}$. That is the term added to `common`.

4. When the gap is $h$ or more, the base of the next branch sits at or above the tip of this one and the two share nothing, so `if (dis < h)` skips the pair.

5. On its own each branch covers $\frac{dh}{2}$, so `ttl` holds $n$ of those, and `ttl - common` is what the tree actually covers.

## Complexity

- **Time:** $O(n)$ per test case — one pass over the gaps between neighbours, with reading the input as the real cost.
- **Space:** $O(n)$ for the `heights` array, though only the previous height is ever needed.

## Notes

- The cast in `(long double)n*d*h/2` is on the first factor so the whole product is worked out in floating point. With $n, d, h$ each up to $2 \cdot 10^5$ the product reaches $8 \cdot 10^{15}$, which a 32-bit `int` cannot hold.
- `d`, `h` and `dis` are all `int` as well, so `(long double)d*(h-dis)*(h-dis)` needs its cast for the same reason. Dividing by $2h$ last keeps it to one rounding step per pair.
- The answer is accepted within $10^{-6}$ relative error, so `long double` printed at `setprecision(10)` has room to spare.
