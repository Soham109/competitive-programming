# Rudolph and Christmas Tree

> [Problem on Codeforces](https://codeforces.com/problemset/problem/1846/D)

## Idea

Every branch is the same triangle, just slid up the trunk, so at any height they share, the branch with the lower base is the narrower one. That single fact kills the hard part of the problem. Whatever branch $i$ shares with a branch two or more above it already lies inside what it shares with its immediate neighbour, so inclusion-exclusion never reaches a third term. The area is $n$ full triangles minus one correction per adjacent pair.

## Approach

1. Write the shape down. Branch $i$ covers heights $y_i$ to $y_i + h$, and at height $t$ its half-width is $\frac{d}{2}\left(1 - \frac{t - y_i}{h}\right)$, which shrinks as $t$ climbs toward the apex. Two branches at the same height therefore compare by base alone, and the lower base gives the smaller width.

2. Push that comparison one step further. Any point shared by $T_i$ and $T_{i+2}$ sits above $y_{i+2} > y_{i+1}$ and is narrow enough for $T_i$, so it is narrow enough for $T_{i+1}$ as well and lies inside it. Overlaps with distant branches add nothing new, which is why the loop only ever reads the gap `heights[i+1] - heights[i]`.

3. Measure one overlap. Since $T_i$ is the narrower shape above $y_{i+1}$, the shared region is simply the part of $T_i$ above that height, a triangle similar to the original with height $h - dis$ where `dis` is the gap. The similarity ratio $\frac{h - dis}{h}$ scales the base to $\frac{d(h - dis)}{h}$, giving area $\frac{d(h - dis)^2}{2h}$, exactly the term accumulated into `common`.

4. Guard the case where nothing is shared. A gap of $dis \geq h$ puts the next base at or above the apex below it, so the branches only ever touch at a point, and `if (dis < h)` skips the pair.

5. Subtract once and print. Each branch contributes its full $\frac{dh}{2}$ to `ttl`, and each adjacent pair gives back one overlap, so `ttl - common` is the union area.

## Complexity

- **Time:** $O(n)$ per test case — a single pass over consecutive gaps, with reading the input as the real cost.
- **Space:** $O(n)$ for the `heights` array, though only the previous value is ever needed.

## Notes

- The cast in `(long double)n*d*h/2` sits on the first factor on purpose, so the whole product is evaluated in floating point. With $n, d, h$ each up to $2 \cdot 10^5$ the product reaches $8 \cdot 10^{15}$, far past what a 32-bit `int` holds.
- `dis`, `h` and `d` are all `int`, so `(long double)d*(h-dis)*(h-dis)` needs its cast for the same reason. The division by $2h$ happens last, which keeps the one rounding step per pair.
- Answers are accepted within $10^{-6}$ relative error, so `long double` at `setprecision(10)` leaves a wide margin.
